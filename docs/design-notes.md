# 设计笔记：内建的行为增强

Luckagent 的飞书桥接链路里有 16 项「不显眼但救过命」的行为增强。它们源自真实生产部署里踩过的坑，**已全部内建进代码**、随框架默认生效——本文是它们的索引：每项一个字母代号，源码中以 `[design-note X]` 注释标记改动位置与取舍说明（个别早期项为不带代号的 `[design-note]` 注释），方便你在读代码时对号入座。

代号使用 A–S，其中 **I / J / O 为空洞**：I、J 曾是飞书「话题（thread）」相关的行为，因话题功能在实际部署中停用、长期零触发而移除；O 预留给一个搁置的产物投递重构方案。编号不重排，避免历史注释失配。

## 代号索引

| 代号 | 名称 | 行为 |
| :---: | --- | --- |
| A | groupOnly 私聊闸门 | `groupOnly: true` 时 bot 只在群聊工作，私聊仅 `groupOnlyAllowUsers` 白名单（如管理员）可用；并按 `message_id` 去重飞书 webhook 的重复投递 |
| B | 上传文件持久保留 | 聊天里发来的文件下载进持久的 `inputs/` 目录（配置了 `downloadsDir` 的 bot），任务结束不清理，之后随时可引用 |
| C | 快速连发合并 | 同一发送人短时间连发的多条消息合并成一个任务处理，而不是排队逐条各跑一轮 |
| D | 引用回复式完成通知 | 群聊中任务完成的通知改为对触发消息的「引用回复」，飞书会精确通知到提问人，而非淹没在群消息流里 |
| E | 开轮清空发送目录 | 每回合开始清空该 chat 的发送暂存目录，根治「这一轮把上一轮的图片又发了一遍」（取舍见下，与 Q 配套） |
| F | 提问卡 @ 提问人 | agent 抛出选择卡（AskUserQuestion）时 @ 提问人，防止 5 分钟无人应答超时作废 |
| G | 出站脱敏 | 发往聊天的文本强制过滤本机绝对路径与密钥形态字符串；文件名（带扩展名）保留，只抹目录结构 |
| H | 注入提问人 open_id | 把当前提问人的 open_id 注入每回合提示词，bot 做授权、发权限等操作时不再猜「你是谁」 |
| K | 上传超时重试 | 飞书文件/图片上传加单次超时 + 指数退避重试，防接口偶发 502 / 请求挂起静默丢文件 |
| L | 发送失败明确告知 | 重试仍失败的文件在群里点名告知文件名与原因，绝不静默丢弃 |
| M | 工作区初始模板 | 新 bot 工作区的 `CLAUDE.md` 使用精简的两级模板体系（见下） |
| N | 超大附件分片下载 | 超 100MB 附件（单次 GET 报错）自动转 HTTP Range 分片下载；下载失败不再静默——提示词里写明文件名与原因；群聊媒体缓存 TTL 30 分钟，过期丢弃打 WARN |
| P | 引用上下文注入 | 群聊「引用回复 + @bot」时把被引消息内容注入回合上下文：自家消息走出站台账回捞（卡片存终版文本、媒体存 key 可重下），他人消息经消息接口拉取，被引图片/文件落地为本地文件喂给 agent；任何环节失败都降级提示、绝不影响本回合 |
| Q | 发过即删 + 漏发补扫 | 发送暂存目录生命周期补全：发送成功**立即删除**（「目录里还有 = 一定没发过」，所有入口天然免疫重复发送）；三处补扫把清理前的残留**先发出去再删**——后台任务回合结束后落盘的迟到产物落盘即发；per-chat 发送互斥防并发双发 |
| R | 后台任务卡片去代码化 | 运行卡片的「后台任务」区块不再直接上屏 shell 命令原文：经 tool_use_id 关联回模型写的人话描述，关联不到显示「后台命令」；回显判重丢弃、展示文本去 URL；失败/中止永远逐条置顶、运行中合计上限 6 条溢出折叠、已完成折叠为计数；终态卡片整块隐藏 |
| S | 私聊也需 @（可选） | `privateRequireMention: true` 时私聊也要 @bot 才响应（飞书私聊的 @ 选人框里有机器人），判定与群聊一致：未 @ 静默忽略、图片/文件暂存等下次 @ 自动带上；同时取消「两人群视同私聊免 @」的豁免，两人群按普通群规则走。`groupNoMention` 只管群聊，两开关互不干涉。默认关 = 私聊直答 |

## 关键取舍

### E 与 Q 的配合：发送目录的完整生命周期

E（开轮清空）根治了「重复发上一轮图片」，但独立存在时有一个已知缺口：**跨回合的后台任务**（比如慢速生图在回合结束后才把文件写进发送目录）会被下一回合的开轮清空、或 5 分钟延迟清理**静默销毁**——这是真实发生过的生产事故。

Q 关闭了这个缺口：发送成功立即删除，于是清理动作面对的任何残留文件都「一定没发过」，三处清理点（自发卡片发出后、开轮清空前、延迟删除前）都会先补扫发送再删。重复发送由「发过即删」物理杜绝，迟到产物由「补扫」兜底送达。**E 和 Q 是一对，不应单独理解**——目录语义详见[目录结构](directory-layout.md)的「⚠️ outputs 归档目录 ≠ 发送暂存目录」一节。

### P 的范围与依赖

- 引用**他人**的消息需要应用具备消息读取权限（见[飞书应用配置](feishu-app-setup.md#第四步配置权限)）；租户未开通时优雅降级，引用 bot 自己的消息不受影响。
- 「自家消息」的回捞依赖**出站台账**：bot 每次发出的卡片终版文本与媒资 key 记录在 `~/.luckagent/outbound-ledger.db`（`SESSION_STORE_DIR` 可改）。台账在仓库之外，升级不影响已积累的数据。
- 被引媒体优先复用 B 保留在 `inputs/` 的历史文件，避免大文件重复下载。

### M 对应的工作区模板

M 指的是 `src/workspace/` 下的两级模板：bot 层 `CLAUDE.md`（专属事实）+ 父目录共用规范 `PROJECTS-CLAUDE.md`（文件约定、出站纪律、CLI 速查）。模板承载了一套具体的协作约定（如 lark-cli 必须显式带身份），不合口味可以直接改模板文件——分工原则见[技能体系](claude-code-skills.md#工作区指令文件两级模板)。

### G 的覆盖面

路径脱敏规则以类 Unix 路径形态为主（`/Users/…`、`~/…`、`/tmp/…` 等），Windows 风格路径基本不在覆盖面内。脱敏是**最后一道防线**，第一道仍是工作区规范里的出站纪律（不往聊天里贴本机路径与密钥）。

## 适用范围与开关

使用前值得知道的三件事：

- **中文 UX**：这些行为产生的用户可见文案（如「⚠️ 有文件没发出来」）与注入给 agent 的提示词均为中文硬编码，非中文团队需自行替换文案。
- **实现于飞书发送链路**：全部增强围绕飞书 sender/事件链路实现；其他接入方式拿不到这些行为。
- **除 A、S 外均为 always-on**：只有 A 的 `groupOnly` / `groupOnlyAllowUsers` 与 S 的 `privateRequireMention` 走 `bots.json` 配置（都不配即默认行为：私聊直答、群聊需 @）。S 做成开关是因为它改的是「私聊要不要 @」这种部署偏好，不是所有部署都会踩的坑。其余 14 项——消息合并、开轮清空、出站脱敏、@提问人、引用注入等——都是无开关的默认行为；这是刻意的取舍：它们修的是「所有部署都会踩」的坑，可配置化只会增加组合爆炸的测试面。确实不想要某一项，请在源码里按 `[design-note X]` 标记定位后自行调整。
